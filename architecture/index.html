One-person architecture

Small system, explicit invariants.

No application server, authentication, cloud database, hosted search or custom synchronization layer is required.

Static compiler

Node 22 validates canonical JSON, generates HTML, compact search assets, geographic shards and Android-friendly packages. Hosting serves files only.

Immutable identity

UUID entity IDs do not depend on names, slugs, coordinates, categories or providers. Redirects and tombstones model merges and removals.

Catalogue vs personal state

Catalogue packages are replaceable. IndexedDB records are independent, exportable and retain last-known snapshots for IDs absent from later catalogues.

Typed custom metadata

A common entity core is extended by configured, validated namespaces. Searchable and faceted fields are declared rather than hidden in prose.

Search

A compact global inverted index identifies candidate IDs and country packages. Full search documents are fetched only from implicated shards.

Map

A centroid overview supports low zoom. At detail zoom, z5 geographic shards load after map movement settles; viewport, quality and personal filters stay active.

Android contract

The stable catalogue manifest lists versioned, hashed full-refresh packages. Android should cache catalogue data separately from backup-worthy user state.

Report seam

Entity pages open a prefilled GitHub Issue carrying immutable ID and current name. Reports trigger investigation, never automatic deletion.

Canonical workflow

research JSON → validate / normalize → explicit editorial approval → static build
               ↘ candidates / rejected findings remain unpublished
browser personal state ↔ portable JSON backup (independent of catalogue refresh)
